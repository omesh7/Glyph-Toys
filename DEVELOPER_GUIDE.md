# Nothing Phone (4a) Pro - Glyph Toy Developer Guide

## 📱 Hardware Context
- **Device:** Nothing Phone (4a) Pro (Release: March 2026)
- **Interface:** Glyph Matrix (Circular 13x13 Grid)
- **Addressable LEDs:** 137 independently controllable mini-LEDs.
- **Physical Controls:**
    - **Glyph Button (Power Button):**
        - **Short Press:** Cycle through active toys.
        - **Long Press:** Trigger "Action" within the current toy.
- **Sensor Integration:** Accelerometer/Gyroscope and Magnetometer are commonly used for interactive toys (e.g., Compass, Spirit Level).

## 🛠️ SDK & Development Setup
- **SDK Version:** `GlyphMatrixSDK v2.1+`
- **Device Identifier:** `Glyph.DEVICE_25111p`
- **Key Classes:**
    - `GlyphMatrixManager`: Singleton for controlling the LEDs.
    - `GlyphMatrixFrame`: Container for 13x13 (169-length) brightness arrays.
    - `GlyphMatrixService`: Base service for background execution (AOD-compatible).

## 🎯 Architecture
Glyph Toys are implemented as **Android Services** to allow them to function when the device is face-down (Glyph interface active, main screen off).

1. **Manifest Registration:** Register your service with `com.nothing.glyph.toy.SERVICE` intent filter.
2. **Lifecycle:** Nothing OS binds to your service when selected from the Glyph menu.
3. **Always-On Support:** Set `com.nothing.glyph.toy.aod_support` to `1` in metadata for low-power updates (e.g., for clocks or meditation timers).

## 🌐 Community Reference: Nothing-Developer-Programme / GlyphMarquee

Cross-checked our services against [`bluehomewu/GlyphMarquee`](https://github.com/bluehomewu/GlyphMarquee), a community-maintained Glyph Toy with multi-device (Phone 3 + 4a Pro) and AOD support. It ships no LICENSE file, so we don't vendor its code — instead we wrote our own clean-room versions of the useful patterns into [`shared/`](./shared/README.md) for new toys to copy from:

- **Official SDK source:** the vendored `GlyphMatrixSDK.aar` is published at [Nothing-Developer-Programme/GlyphMatrix-Developer-Kit](https://github.com/Nothing-Developer-Programme/GlyphMatrix-Developer-Kit) — check there for newer SDK releases before hand-patching the `.aar`. (Confirmed: our current `.aar` already exposes `Common`, `GlyphMatrixObject`/`GlyphMatrixFrame` builders, and `GlyphToy.EVENT_AOD` — no upgrade needed for the patterns below.)
- **Multi-device detection** ([`shared/GlyphDeviceUtils.kt`](./shared/GlyphDeviceUtils.kt)): rather than hardcoding `Glyph.DEVICE_25111p`, call `Common.getDeviceMatrixLength()` at connect time and register against the matching device constant (`Glyph.DEVICE_23112` = Phone 3, 25×25; `Glyph.DEVICE_25111p` = Phone 4a Pro, 13×13). Scale frame/text sizing off the returned length instead of a literal `13`/`169`. Our current toys only target the 4a Pro, so this only matters if/when we add Phone 3 support.
- **Newer builder-style rendering API:** `GlyphMatrixObject.Builder().setImageSource(bitmap).build()` → `GlyphMatrixFrame.Builder().addTop(obj).build(context)` → `gmManager.setMatrixFrame(frame)`. Our toys currently push raw 169-length brightness `IntArray`s directly — both are valid, but the builder API is worth using for anything that composites multiple layers (e.g. text + icon).
- **AOD lifecycle handling** ([`shared/AodLifecycleGuard.kt`](./shared/AodLifecycleGuard.kt)):
  - The system sends `GlyphToy.EVENT_AOD` roughly once/minute; only react to the *first* event that starts a session and ignore repeats while already running, or animations jump back to the start.
  - `onUnbind` is **not** reliably called on every screen wake — register an `ACTION_SCREEN_ON` `BroadcastReceiver` instead if you need to detect "user woke the screen" to reset state.
  - Delay ~500ms before turning off LEDs / stopping the loop in `onUnbind`/screen-off — brief system rebind/unbind churn during AOD transitions otherwise causes visible flicker.
